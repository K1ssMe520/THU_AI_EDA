# 实验一：单次 Prompt 驱动的 RTL 生成

每条正式实验轨迹固定为：

```text
冻结规格 + 一条 Prompt → 单次 API 调用 → 原始 RTL → 教师 TB 验收
```

测试报告只用于实验分析。若要补充需求，必须使用新的 Prompt 和新的 `run-id`，不能修改已生成 RTL，也不能把同一次运行的报告回传给模型。

## 课堂题：`classroom_seq1011`

课堂题实现带 ready-valid 接口、允许重叠的 `1011` 串行序列检测器。

| 条件 | Prompt 策略 | 对照目的 |
| --- | --- | --- |
| P1 | 一句口头需求，不限定输出格式 | 展示模块名、接口与输出都不受控时，回答难以提取、且夹杂大量无用文字。 |
| P2 | 精确接口 + 只输出 RTL，功能只给一句话 | RTL 可稳定提取并接入教师 TB；握手、延迟、反压与复位均未定义，通常无法工作。 |
| P3 | 补上 ready/valid 握手与低有效复位的基本语义 | 明确握手信号与复位逻辑，但输出延迟、吞吐、反压保持与同步复位仍未定义，仍可能失败。 |
| P4 | 根据 P3 运行结果做最小增量补充（延迟、吞吐、反压、同步复位） | 模拟真实情况下需求逐步修正，最终形成可工作的完整契约。 |
| P5 | P4 + 独立思维链小节，指导最小状态机与低面积/低功耗实现 | 在功能等价前提下比较综合面积与功耗活动。 |

课堂任务的测试报告会在安装 Yosys 后增加 `metrics.area`。该值采用 VerilogPAD 附带的 45 nm 库，仅用于同一工具版本、同一库和同一脚本下的相对面积比较。

## 课后题：`homework_aes128`

课后题要求用**一个** SystemVerilog 模块实现 AES-128 加密（FIPS-197）：内部可以包含密钥扩展、S-box、行移位、列混合和轮控制等多个层次，但必须在一个 `module` 内完成，禁止例化其他模块或引用外部文件。教师 TB 检查标准向量、连续加密、忙时复位与握手时序；功耗脚本生成 VCD 后估算动态/漏电功耗。

工作台的「课后作业」页没有 Prompt Stage，只提供只读 Spec 与一个空白 Prompt 编辑器。学生需自行写出包含算法分解、接口/时序约束、实现方案对比和面积/功耗优化思维链的完整 Prompt；评分同时考虑教师 TB 是否通过以及相同模型配置下的面积/功耗 metric。

```sh
.venv/bin/python -m common run --task homework_aes128 --prompt homework/H1_custom.md --run-id hw-r01 --temperature 0.2 --max-tokens 8192
```

旧的 `homework_sync_fifo` 任务保留用于复现历史同步 FIFO 实验记录。完整运行命令、Ubuntu 安装方法和提交要求见顶层 `teaching.md`。
