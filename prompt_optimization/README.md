# 实验一：单次 Prompt 驱动的 RTL 生成

每条正式实验轨迹固定为：

```text
冻结规格 + 一条 Prompt → 单次 API 调用 → 原始 RTL → 教师 TB 验收
```

测试报告只用于实验分析。若要补充需求，必须使用新的 Prompt 和新的 `run-id`，不能修改已生成 RTL，也不能把同一次运行的报告回传给模型。

## 课堂题：`classroom_seq1011`

课堂题实现带 ready-valid 接口、允许重叠的 `1011` 串行序列检测器。

| 条件 | Prompt 策略 | 对照目的 |
| --- | --- | --- |
| P1 | 一句口头需求 | 展示输出格式、模块名和接口都不受控时的提取问题。 |
| P2 | 精确接口 + 只输出 RTL | 使 RTL 可提取并能接入 TB。 |
| P3 | 明确握手、延迟、反压、重叠和复位 | 建立完整功能契约。 |
| P3.1 | 仅补充同步复位敏感列表语义 | 模拟根据前一版生成发现一个歧义后做最小需求澄清。 |
| P4 | P3.1 + 最小 FSM 的内部推导 | 在功能等价前提下比较综合面积。 |

课堂任务的测试报告会在安装 Yosys 后增加 `metrics.area`。该值采用 VerilogPAD 附带的 45 nm 库，仅用于同一工具版本、同一库和同一脚本下的相对面积比较。

## 课后题：`homework_sync_fifo`

课后题比较 P0（功能描述）、P1（完整契约）和 P2（契约加内部检查清单）。每种条件至少独立运行三次，固定模型配置与教师 TB。学生不能修改 `tasks/` 中的规格和 TB。

完整运行命令、Ubuntu 安装方法和提交要求见顶层 `teaching.md`。
